Collect answers as the paper did: one answer per question with the prompt as given; greedy decoding with up to 3,072 new tokens, or, for reasoning models, temperature 0.6, top-p 0.95 and top-k 20 with up to 12,288 tokens. The author responses found that temperature does not move a model's position but a system prompt does, so reference and query answers must share a system prompt.
  4. Question ids, benchmarks and pool membership: questions.csv. Prompts, gold answers and graders are in the code release (data/core/probe.jsonl).

How it works

BULLPEN embeds a model from three channels of its answers to a fixed probe: its correctness bits, the text of the questions it got right (a correctness-weighted mean question embedding), and the text of its own answers (mean BGE answer embedding). Closed-form multi-block PLS-SVD fits per-channel loadings, and the code concatenates each channel's z-scored scores: 12 + 10 + 10 dimensions for BULLPEN-fused, 16 + 16 for BULLPEN-bits+q (bits and question text only).

Everything shown is fitted with the released code on fold 0, seed 0 of the paper's strict protocol (publisher-grouped folds over models; the 900 pool questions). A new model is placed by the paper's fold-in: a ridge solve of its observed bits on the frozen bit loadings, its question block from those bits, and a projection of its mean answer embedding. Every map is linear, so the page evaluates them directly from exported weights; no model runs here. The heads are the paper's battery readouts (standardised ridge, or logistic for base vs chat) refitted once on the 208 training models.

Limits. The submission scores the heads on held-out models from the 260 open-weight models; the author responses add nine closed models placed without refitting (below). One split and one seed are shown, so per-model values here are single draws, not the paper's averages over 15 runs. The base-vs-chat label comes from the model name, as in the paper.
